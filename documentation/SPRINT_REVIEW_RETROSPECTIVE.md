## 4. Retrospective

### What Went Well

- Core reservation functionality was implemented successfully.
- Backend and frontend responsibilities were separated clearly.
- Automated backend testing provides strong coverage.
- CI automates backend and frontend quality checks.
- Production deployment was completed.
- API and system documentation were developed alongside the implementation.
- The architecture remained within the original project scope.

### What Could Be Improved

- Collaborative development evidence should have been maintained more consistently from the beginning.
- Formal sprint records should have been maintained continuously.
- Code review evidence should have been captured during development rather than reconstructed later.
- Project documentation and UML evidence could have been maintained closer to the time of implementation.
- Deployment and release evidence should have been recorded as part of the development workflow.

### Actions for Improvement

1. Maintain a current backlog until final submission.
2. Record significant architecture and implementation decisions.
3. Keep CI checks active for future changes.
4. Use the code review checklist for significant changes.
5. Maintain release/version records.
6. Keep final QA, deployment and handover documentation synchronized with the implementation.
